# 灵析 · 科技信息去噪

灵析帮助读者整理科技公众号文章。多篇文章报道同一件事时，它把这些文章放在一起，比较各篇提供了什么信息、哪些说法有依据、哪些只是作者的判断，再推荐最值得读的一篇。

这个版本已经可以演示完整的阅读过程，也支持导入文章正文。公众号自动采集和真实模型服务还没有连接。

## 现在能做什么

- 查看 6 个事件、24 篇文章组成的演示工作台。事件、文章和评分都是虚构的，界面会标明“演示”。
- 按话题、关键词、时间和是否读过筛选事件，也可以按讨论数量或文章质量排序。
- 收藏事件、查看阅读记录、导入正文。正文完全相同的文章不能重复导入；标题相似的文章会先分到同一组。
- 在当前浏览器中保存文章、收藏和阅读记录。你可以把这些数据导出为 JSON 文件，也可以把事件简报导出为 Markdown 文件。
- 连接 LLM（大语言模型）后，让它对比同一事件下的文章。服务未配置时，接口会返回 503，文章仍然保存，界面显示“待分析”。
- 核对模型引用的文章和原句。如果引用的句子在对应正文中找不到，程序会拒绝这次分析结果。模型没有查询外部资料，因此不能把真实文章中的说法标成“已核验”。

## 怎样连接模型服务

如果使用 Sites 部署，在站点的运行环境中设置以下变量。密钥只交给服务端使用，不要写进源码或浏览器代码。

- `LLM_API_KEY`：你授权使用的模型服务密钥。
- `LLM_BASE_URL`：模型服务的 HTTPS API 基础地址，应包含服务要求的版本路径。程序会在这个地址后追加 `/chat/completions`。
- `LLM_MODEL`：该服务支持的模型名称。

服务需要兼容 Chat Completions（聊天补全接口），并支持 JSON mode（按 JSON 格式返回结果）。用户点击“交叉分析”后，程序才会把导入的正文发送给模型服务。

一次最多对比 12 篇文章，每篇正文最多 16,000 字，所有正文加起来最多 72,000 字。请求超过 55 秒会中止。调用失败时，界面会提示原因，文章仍保存在浏览器中，可以稍后重试。

程序只分析导入的正文，不会自动打开原文链接，也不会上网查证。若使用 OpenAI 密钥，需要通过 Sites 的 OpenAI Developers 插件完成授权和配置。

## 怎样接入公众号文章

目前没有连接微信账号、文章服务或 RSS（内容订阅源）。在界面里添加公众号名称，只会把它加入来源列表，不能直接读取用户在微信里关注的公众号。

现在可以先复制文章正文，再通过“导入文章”添加内容。要让应用自动收集文章，需要连接一个允许你使用的文章接口或订阅服务。

后续接入时，可以按以下步骤处理：

1. 采集服务从用户授权的来源获取文章，保存标题、作者、发布时间和原文地址。
2. 程序删去菜单、广告等无关内容，并检查链接和正文，避免把同一篇文章保存多次。
3. 程序比较文章提到的公司、产品版本和发生时间，把报道同一件事的文章分到一组。只提到同一家公司的文章，不一定属于同一个事件。
4. 模型逐篇比较事实、观点和新增信息，说明哪些文章值得读、哪些结论缺少依据。
5. 程序检查引用是否对应真实文章、引用原句是否存在，然后保存分析结果。检查失败时，不把结果显示给读者。

如果以后需要多个用户使用或跨设备同步，可以用 D1（Cloudflare 的 SQLite 数据库）保存每个用户的信息源、文章、事件和分析结果，用 R2（对象存储）保存经授权获取的正文。采集任务还需要定时执行；重复运行时不能重复保存文章，失败后也要能继续处理。

当前版本最多保存 40 篇导入文章。文章和收藏保存在 localStorage（当前浏览器的本地存储）中，更换浏览器或设备后不会自动出现。

## 怎样理解分析结果

灵析只比较当前事件下已经导入的文章。原创度和重复度反映的是这些文章之间的差别，不能判断一篇文章是不是全网首发。

质量评分由模型给出，帮助读者决定先读哪篇，不是对文章真实性的最终结论。几篇文章说法相同，也可能只是转述了同一条消息，仍然需要核对官方材料或独立数据。

## 本地开发

推荐使用 Node.js 24，版本记录在 `.nvmrc` 中。框架要求 Node.js 至少为 22.13。克隆仓库后，运行：

```sh
git clone https://github.com/sulik0/lingxi-tech-reader.git
cd lingxi-tech-reader
npm run install:ci
npm run dev
```

开发服务的地址是 `http://localhost:5173`。修改后可以运行以下命令检查并构建应用：

```sh
npm run typecheck
npm test
npm run build
```

本地调试模型服务时，把 `.env.example` 复制为 `.dev.vars`，填写配置，再重启开发服务。Git 会忽略 `.dev.vars`，不会上传其中的密钥。部署后则使用平台提供的运行环境配置。

项目使用 Sites 提供的 Vinext / Cloudflare Workers 初始代码。`build/sites-worker.ts` 在收到请求时处理分析接口，并从运行环境读取模型密钥。分析接口只接受从本站发起的 JSON POST 请求；响应包含 `Cache-Control: private, no-store`，要求浏览器和代理不要缓存分析结果。
