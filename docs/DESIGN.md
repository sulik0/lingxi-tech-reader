# 灵析极简前端设计方案

状态：待用户确认。2026-10-11 已检查当前代码；本轮只整理方案，没有修改页面、后端、数据库或线上站点。

## 产品与范围

灵析是个人 AI 科技信息流。打开后先阅读已聚合的资讯，用一句话调整想看的主题，需要时查看机器人推送状态。首页不展示文章正文，不以来源管理、模型用量或长篇报告操作作为主要内容。

本版先服务当前私人站点的使用者。未来多用户是后续需求，不在这次前端改版中增加账号系统或数据库迁移。收藏重新进入首页，但只提供轻量操作，不恢复阅读记录和完整文章库。

## 视觉方案

采用用户指定的 Swiss Minimal / Editorial Minimal：用整齐的对齐、清晰的文字层次和浅灰分隔线组织资讯。借鉴 Linear 的布局精度与 Readwise Reader 的阅读节奏，不照搬导航或装饰。

| 项目 | 方案 |
| --- | --- |
| 页面底色 | `#FFFFFF`，不加渐变或背景纹理。 |
| 主要文字 | `#111111`，标题和关键操作使用。 |
| 次要文字 | `#616161`，用于来源、时间和说明。 |
| 分隔线 | `#E5E7EB`，用于列表行和区域边界。 |
| 蓝色强调 | `#1D4ED8`，用于主操作、链接和键盘焦点。 |
| 轻量底色 | `#F5F6F8`，用于输入区和加载占位。 |

字体优先使用设备上的 `PingFang SC`、`Noto Sans SC`、`Microsoft YaHei` 等中文无衬线字体，英文回退到系统无衬线字体；不引入远程字体请求。品牌 22px，偏好区标题 26px，资讯标题桌面 20px / 移动端 18px，摘要 15px，辅助文字 13px。摘要行高约 1.75，正文列宽尽量控制在约 40 个汉字以内。

桌面内容区域最大宽度约 880px，阅读区约 720px；内容左对齐。使用 4 / 8 / 12 / 16 / 24 / 32 / 48px 间距。输入和按钮圆角 4–6px，资讯不做一组组带阴影的卡片。弹窗可以有轻微阴影。首版不做封面图、数字大屏、新闻门户式多列布局或入场动画。

页面最醒目的部分是自然语言输入，不是营销大标题。列表通过标题、摘要、来源和时间帮助读者判断是否值得打开原文，评分与事实详情只在用户展开时显示。

## 首页与设置

```text
灵析                                              设置
─────────────────────────────────────────────────────
你想关注什么？
[ 不看汽车手机，多看 AI Agent                    ]
                                      [ 解析偏好 ]
当前偏好：关注 …  /  不看 …

解析后才出现：
关注：原来 … → 改为 …
不看：原来 … → 改为 …       [ 取消 ] [ 确认保存 ]
─────────────────────────────────────────────────────
最新资讯       [ 全部 / 收藏 ]              刷新列表

资讯标题                                           ☆
来源名称                         原文发布时间
两到三行聚合摘要 …
主题标签        原文链接                减少类似内容
─────────────────────────────────────────────────────
下一条资讯 …
```

线框里的标题和摘要只是字段示意，不作为真实资讯填充到产品里。没有真实结果时展示空列表；演示数据只能出现在明确标注的独立测试环境。

顶部只保留品牌和“设置”。首页不放固定侧栏、管理面板、推送表单或多步骤流程图。列表工具栏默认按最新原文发布时间排列；“全部 / 收藏”是两个轻量视图，不增加分类导航墙。

设置使用可滚动弹窗，桌面宽度约 560px，移动端接近全屏。主要内容是“机器人推送”；“订阅来源”和“报告与服务”按需展开。沿用当前管理口令，在未连接时展示简洁连接表单，口令只保存在页面内存中，不做假登录。

## 资讯如何展示

一行表示一个 `EventItem` 聚合事件，而不是一篇原始文章。显示以下内容：

- 标题、已有分析摘要和已有主题字段；不调用前端模型编造摘要或标签。当前 `category` 常为“科技资讯”，`tag` 常为“自动采集”，后者不能当主题显示。没有更具体主题时保留“科技资讯”。
- 去重后的来源名称与实际文章数量。数量多时显示前两个来源和“另 N 个来源”，展开后列出其余来源链接。
- 从成员文章的有效 `publishedAt` 取最新发布时间，按这个时间倒序；缺少有效时间的项排在后面，显示“发布时间未知”。`updatedAt` 不冒充原文发布时间。
- 摘要默认两到三行，提供“展开摘要”；更详细的事实、观点和阅读建议按需展开，不把原文正文直接渲染到首页。
- 优先链接到 `recommendedArticleId` 对应的原文；没有明确推荐时提供“来源原文”，不声称它是最佳文章。只有有效 HTTP(S) 链接才显示可点击入口，新窗口打开并设置 `noopener noreferrer`。

默认只显示 `demo=false`、`pending=false` 且有可用摘要的真实事件。待分析的文章不冒充聚合资讯，列表下方仅显示数量和继续处理的入口。现有短 RSS 摘录也标为待处理，不混入“已分析”的列表。综合早报如果已经有可用分析，注明“多主题汇总”，不把它包装成单一事件。

接口目前最多返回 200 条事件。页面注明“最近已分析资讯”，不承诺完整历史。可在这批数据上每次多显示 20 条，但不做没有后端支持的无限历史翻页。

## 偏好：解析、确认、保存

1. 用户输入要求，点击“解析偏好”。调用现有 `POST /api/automation/policy/parse`，不保存、不采集、不生成报告、不发送消息。
2. 页面对比当前与解析后的 `include` / `exclude`，清楚显示新增、移除和保留的关键词。可以编辑关键词或取消。“多看”当前只能转成关注关键词，不能实现推荐权重，必须在预览旁说明“关注关键词会限定显示范围”。不承诺完整理解任意自然语言。
3. 用户点“确认保存”后，调用现有 `PATCH /api/automation/policy`。提交完整策略，保留原来的 `screenEnabled`、`minValue`、`deepLimit`，不因修改主题而重置预算设置。
4. 保存成功后重新读取策略，对已加载事件执行当前关键词规则。复用 `matchPolicy` 的标题和前 600 字检查；整个事件的成员都通过时才显示，避免排除主题通过同组摘要再次出现。这个浏览筛选不重新调用 Jev，也不将其描述为一次新的质量评分。
5. 保存不会调用 `/collect` 或 `/report`。后台在后续任务中使用新要求筛选已入库文章；过去生成或发送的报告仍保留原要求，原始数据不删除。

输入有改动后，之前的解析预览失效，不能保存旧预览。解析失败保留原输入与已保存策略；保存失败保留草稿和确认区域，并明确表示“未保存”。请求进行中禁用相应按钮。发生任务锁冲突时提示稍后重试，不偷偷覆盖或触发第二轮任务。

当前 `collection_policy` 是 `id=1` 的站点级策略，不是个人账号独立策略。第一版设置里说明“偏好会影响此私人站点后续生成的报告和推送”。多用户上线前必须另行设计用户身份、权限和每人的偏好存储，不能靠前端命名空间假装完成隔离。

## 收藏与“减少类似内容”

收藏使用按钮，支持取消。第一版只把事件 ID 和成员文章 ID 保存到当前浏览器的 `localStorage`，不保存正文、口令或密钥，不新增后端表。明确提示“收藏仅保存在当前浏览器，不会跨设备同步”。分组变化时可用文章 ID 寻找新事件；找不到的收藏说明暂时不在本次返回范围，不伪造旧资讯。存储不可用时显示不能保存的原因，不给出持久保存成功提示。

“减少类似内容”先打开小型反馈面板：有可信具体主题时预填建议关键词；只有“科技资讯 / 自动采集”等泛化标签时，要求用户填写要减少的主题，不能一键排除整个科技列表。点击“预览变更”后，展示准备加入的排除词以及将受影响的当前资讯数量，再由用户“确认保存”。该动作复用同一套策略保存流程，保留原关注词和其他排除词。当前后端支持排除，不支持降低推荐概率，面板需要说明“确认后将不再展示命中该主题的资讯”。用户可以在偏好区移除关键词恢复显示。

收藏列表同样遵循当前偏好；被排除的收藏不删除收藏记录，并显示“部分收藏被当前偏好隐藏”。本版不加阅读记录、阅读进度或收藏文件夹。

## 推送设置与可信状态

设置里显示飞书与企业微信两种机器人、每日推送开关和北京时间发送时刻。用户所说的“微信”在现有实现中是企业微信群机器人；个人微信没有接口支持，不能用同一个名称声称已支持。

复用 `/settings` 保存渠道启用状态和时间。Webhook、模型密钥仍由服务端 Secrets 管理；当前没有安全的机器人地址编辑接口，因此弹窗只展示配置状态、开关和配置帮助，不增加把 Webhook 明文提交到现有 API 的表单。邮件已有配置保留，放入“其他渠道”，不能在保存机器人设置时关闭现有邮件或清空收件人。

每个机器人分别展示“配置已填写 / 未配置”“自动推送已开启 / 已关闭”和最近一条实际发送记录。配置已填写不等于连接通过或送达成功；没有记录就显示“暂无发送记录”。发送中、失败、无法确认送达分别展示，不合并成成功。接口记录 `sent` 表示服务已接受发送，不额外声称群成员已阅读。失败原因可展开；不能自动重发 `uncertain` 状态。

已有手动生成和推送能力保留在“报告与服务”里：用户明确点击“检查新资讯并分析”才依次调用 `/collect` 和 `/report`，说明会访问来源并使用模型，但不发送消息。完成后更新资讯列表，同时保留报告预览。用户再点“推送这份报告到飞书”时，才使用既有保存报告发送接口。企业微信只沿用每日自动推送，没有手动发送接口时不加假按钮。生成失败或尚有文章待处理时显示实际结果，不把局部结果说成全部完成。

## 状态、移动端与可访问性

| 状态 | 用户看到什么、可以做什么 |
| --- | --- |
| 首次载入 | 简洁加载行；只有初次没有数据时显示骨架，后续刷新保留已有列表。 |
| 未连接 | 管理口令表单和真实的连接错误；连接前不显示示例资讯。 |
| 暂无资讯 | “还没有已分析资讯”，引导查看来源或在设置里继续处理。 |
| 偏好下为空 | “当前偏好下没有资讯”，提供调整偏好入口，不自动放宽规则。 |
| 收藏为空 | “还没有收藏”，说明可在资讯右侧收藏。 |
| 刷新失败 | 保留旧列表并标记“未能更新”；不要以“没有资讯”替代请求失败。 |
| 解析与保存 | 按钮显示正在处理；解析预览与已保存策略分开；保存成功用内联状态提示。 |
| 推送异常 | 保留渠道和报告的对应关系，显示真实错误或“无法确认送达”。 |

移动端左右留白 16–20px；标题、摘要、来源依次排列，来源与时间可换行，操作触控区域至少 44px。偏好确认按钮在窄屏上下排列；长标题、URL 和关键词不造成横向滚动。设置弹窗有独立滚动区，关闭按钮不随长内容消失。

所有输入有可见标签；收藏用 `aria-pressed`，图标按钮有中文名称；加载与保存反馈使用 `role=status`，错误使用 `role=alert`。设置弹窗复用现有 Radix Dialog 的焦点管理，支持 Escape、键盘导航和关闭后返回触发按钮。蓝色焦点清晰可见；不靠颜色单独表达状态；遵循减少动态效果的系统偏好。

## 与当前代码如何衔接

已核对 `package.json`、`app/page.tsx`、`components/automation-panel.tsx`、`components/collection-policy.tsx`、`lib/data.ts`、`lib/automation/{api,types,policy,store,runner,events,presentation}.ts` 和 `db/schema.ts`。

现有技术栈为 React 19、TypeScript、Next.js App Router 形式的页面，由 Vinext / Vite 构建；样式已有 Tailwind 4 与普通 CSS，图标为 Lucide，弹窗已有 Radix 封装。后端运行于 Cloudflare Workers，数据在 D1，Drizzle 描述表结构。此次继续使用这些工具，不引入新的前端框架、状态库或 UI 套件。

| 现有接口 / 模块 | 前端用途与边界 |
| --- | --- |
| `GET /api/automation/events` | 读取事件、成员来源、摘要与链接；返回正文也不代表前端需要渲染它。 |
| `GET /api/automation` | 读取当前策略、来源、服务配置、推送设置、发送记录与任务状态。 |
| `POST /api/automation/policy/parse` | 只解析输入；复杂输入可能调用一次分析模型。 |
| `PATCH /api/automation/policy` | 用户确认后保存完整策略，站点级生效。 |
| `PATCH /api/automation/settings` | 保存既有推送设置，保留未展示的渠道值。 |
| `POST /api/automation/collect` | 明确检查来源时才调用；不会因为保存偏好而调用。 |
| `POST /api/automation/report` | 使用已入库文章继续分析和生成报告，本身不重新抓取来源或发送消息。 |
| `POST /api/automation/reports/:id/send` | 显式发送既有手动报告到飞书，继续遵守发送时限和重试限制。 |
| `CollectionPolicyEditor`、`ReportBody`、`presentation.ts` | 复用策略交互逻辑、报告正文展示和真实状态映射，按新布局拆分。 |

保留现有 Bearer 管理口令、写请求同源检查与后台任务锁。不会改认证接口或增加浏览器里的服务密钥。用小型前端组件分别处理连接、偏好、资讯行、收藏和设置；数据获取集中处理，写操作只在用户动作中触发，避免因为重渲染或轮询重复调用模型。批量读取相互独立的两个 GET，取消过期请求，忽略旧响应，局部失败分别提示。

采集与偏好过滤已在现有后端分开：采集保留原文章，策略用于后续筛选。此次前端让保存偏好只写策略、重算当前列表，不改变这条处理顺序。既有原始数据、历史事件、报告和后台保留期限均不改动。

## 确认后的实施与验收

确认后，先按 `frontend-design` 落实样式与页面结构，再按 `react-best-practices` 实现组件，最后使用 `web-design-guidelines` 检查 UI/UX 并修复问题。运行类型检查、已有测试与构建；为规则预览、排序和收藏等容易出错的行为补充必要测试。

通过当前会话允许的 Playwright 方式，在本地验证以下场景；使用模拟接口的场景必须明确标注，不能作为真实服务验收。没有用户明确发送动作，不向真实群发送测试消息。

- 连接、读取真实数据或显示真实错误；无数据与待分析状态；刷新失败保留已有内容。
- 输入“不看汽车手机，多看 AI Agent”，解析后未保存，确认后保存并更新显示；取消、修改输入、保存失败、后台忙等分支。
- 保存偏好时没有 `/collect`、`/report` 或发送接口请求；首页刷新只读取数据；关键词筛选不会展示被排除成员的共享摘要。
- 收藏、取消收藏、刷新恢复、收藏为空、存储不可用；减少类似内容先预览再确认，取消不写策略。
- 设置打开、关闭、键盘焦点与 Escape；企业微信和飞书分开显示配置、开关与发送记录；保存不重置邮件设置。
- 1440 / 1024 / 768 / 390 / 320px 宽度下检查长标题、长来源和长关键词，确认无横向溢出或操作遮挡；截图检查文字密度与阅读顺序。
- 检查控制台错误、页面异常和失败请求，区分主动模拟的错误状态与未处理错误。构建成功不能替代这些检查。

本轮交付为方案文档。用户确认前不开始页面实现；确认后的首轮开发也以本地验证为界，不自动发布或更改私人站点受众。需要后端支持的新能力另行说明，不擅自实现。
