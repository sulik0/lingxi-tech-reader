# 灵析极简前端设计

用户已确认 Swiss Minimal / Editorial Minimal 风格；2026-10-11 要求将检索与报告放在首页，2026-10-16 要求改为每条资讯一张卡片的瀑布流。当前首页围绕“生成、阅读、按需发送”组织，不展示报告次数、历史列表或原始文章库。历史数据和发送记录继续保存在后台。

## 视觉与页面结构

沿用白底 `#FFFFFF`、主文字 `#111111`、辅助文字 `#616161`、浅灰分隔线 `#E5E7EB`、蓝色操作与链接 `#1D4ED8`。字体优先设备上的中文无衬线字体，不增加远程字体。页面最宽 1240px，内容左对齐；宽屏三列、中屏两列、700px 以下单列。卡片按内容自然撑高，使用 CSS columns 排列，不增加测量布局的脚本。标题 30px，卡片标题 20px，摘要 14px，辅助说明 12px。移动端缩小标题并让主按钮占满一行。

打开首页自动读取报告，不设置管理口令输入页，也不提供“退出连接”。首次读取时显示加载状态，失败时提供重试。没有内容时明确提示开始检索或没有符合要求的资讯，不填充假摘要。设置只维护来源、每日自动推送、服务与模型用量；不重复首页主操作，也不提供历史报告选择器。收藏与阅读记录暂不展示，旧数据和组件不删除。

## 检索、生成与结果

1. 点击首页主按钮，只采集一次，再整理最近 24 小时的文章。前端自动继续同一份报告直到完成，不让用户理解后台处理次数。
2. 处理中禁止重复开始，展示真实阶段和文章处理进度。遇到模型、网络或来源错误时保留已有结果并提示原因。没有推进时停止继续请求，避免无限重试。
3. 首页只展示最新报告，包括最新的空结果或错误，不将旧成功报告冒充本次结果。正常完成后直接以资讯卡片阅读，不需要再打开设置或选择历史。卡片使用已保存报告中的事件摘要与要点，不展示文章质量评分、推荐理由和冗长阅读建议；事实、观点与尚不确定事项默认折叠。来源域名来自原文链接，不把报告生成时间冒充文章发布时间。已保存报告和推送内容保留，改变展示不额外调用模型。
4. 比较报告内容而不是报告编号：仅新建记录或改变标题日期，不足以声称“有新报告”。相同正文提示暂无新报告；后台出现不同内容时，刷新会提示有新报告。
5. 未完成但仍可继续的报告提供“重试未完成的资讯”，复用原范围、不重新采集。发送后的报告、过期报告和改变要求后的报告不能继续改写。
6. 偏好改变不改写已有报告，页面说明需要再次检索。生成与刷新不自动发送消息。

后台容量、文章筛选、模型引用和更新规则集中维护在[自动订阅与推送](automation.md)和[搜集要求与模型开销](collection-policy.md)，不在本页重复。

## 按需发送

生成后点击“选择发送渠道”，勾选飞书、企业微信或邮件，再点击“发送到所选渠道”。默认不勾选，不因为每日设置而自动发送。未配置、缺少收件人、已发送、送达不明、正在发送或超过重试次数的渠道不能选择。

只发送当前保存的报告，不重新采集、不重新分析、不改变自动推送开关。各渠道分别保存状态：向飞书发过后，仍可选择企业微信或邮件；已经发送的渠道不会重复发送。接口接受表示服务接收请求，不代表用户已读。个人微信目前不支持。

## 自然语言偏好

展开“调整信息偏好”，输入要求并点击“解析偏好”。展示关注与排除词的变更后，由用户确认保存。解析和保存不调用采集、报告或发送接口；复杂条件当前只能转成关键词，预览说明实际含义。保存保留现有模型开关和处理配置。

## 确认后的实施与验收

使用 frontend-design 确定布局与文字层次，遵循 React 实现规范，按 Web Interface Guidelines 检查按钮语义、状态提示、标签、焦点、链接和溢出。浏览器验收至少覆盖首页开始、自动继续、报告直读、渠道选择与重复发送保护、没有新内容、错误恢复、偏好确认，以及桌面和 390 / 320px 布局。模拟接口不能当作真实模型或群消息验收。记录见[阶段验收](acceptance.md)。
