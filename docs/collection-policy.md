# 搜集要求与模型开销

## 从哪里调整

连接首页后，在“你想关注什么？”输入要求，点击“解析偏好”，查看与当前关键词的对比，必要时编辑关键词，再点击“确认保存”。保存后立刻重新筛选已有事件，不调用采集或生成接口；之后后台任务也采用新规则。点击“减少类似内容”时同样先预览排除词，再确认保存。界面限制与收藏行为见[前端设计](DESIGN.md)。

简单的“关注 AI 和芯片，不关注汽车手机”由程序解析，不调用模型。复杂句子会调用现有 `LLM_*` 模型一次，返回关注和排除关键词；解析不自动保存，也不触发采集或推送。规则并不保留任意自然语言条件，例如“只看有三年经验作者的文章”不能靠关键词准确执行；请检查结果并改成明确的主题要求。

关注关键词满足任意一个即可；排除关键词优先。汽车、手机、AI、芯片匹配代码中列出的常见相关词，其他关键词按标题和前 600 字匹配，英文词不匹配更长英文单词中的片段。规则可能遗漏没有出现关键词的相关报道，也可能排除偶然提到该主题的文章。包含排除主题的多主题早报整篇跳过，当前不从早报中拆出部分新闻。

这些要求筛选已配置 RSS/Atom 的文章，不会发起全网搜索，不会改变来源地址。原始文章仍保留，以便调整要求后重新处理。只有整个事件的文章都通过筛选才进入报告，防止被排除的内容通过同组摘要再次出现。新要求用于之后生成的报告，已经生成或发送的报告保持原样；报告正文和页面记录当时采用的要求。

## 配置 Jev

在项目根目录的隐藏文件 `.dev.vars` 中填写：

```dotenv
JEV_API_KEY=你的Jev密钥
JEV_MODEL=jev-1.13.0
```

已有 `.dev.vars` 时只编辑对应项，不要复制模板覆盖其他密钥。本地填写后重启服务；线上要在同一个 Sites 项目的 Secrets 中添加 `JEV_API_KEY`，`JEV_MODEL` 可作为普通环境变量。不把密钥放在浏览器、Git 或聊天里。本地文件不自动同步到线上。

使用 [TypeSafe 官方接口](https://docs.typesafe.ai/api)：向 `https://api.typesafe.ai/v1/systemone` 发送 `state` 和 `questions`，每篇文章提出一个 Score 问题，五档描述从“只有推广或空泛情绪”到“丰富技术细节、数据或深入分析”。Score 返回 0–4 的加权分数，程序换算为 0–100；默认最低值为 40。模型版本固定为 `jev-1.13.0`，可用 `JEV_MODEL` 调整，避免别名升级后继续使用旧版筛选缓存。

Jev 只判断是否值得继续阅读，不生成报告，也不核实事实。它每篇只读取标题、来源和前 300 字摘录。`confidence < 0.65` 时保留文章，避免凭不确定的低分丢掉内容。明确低于最低值且把握足够时跳过完整分析。阈值是当前产品的保守初值，还没有完成真实文章的人工标注验证，可以在“控制 AI 用量”中调整。

评分校验要求五档概率齐全、数值在有效范围内，并与加权分数一致。HTTP 响应会把各数值保留两位小数；校验按五个概率分别舍入的最大误差留出容差，不再将正常舍入判为“结果不完整”。缺少档位、越界或明显不一致仍拒绝，不因此放行未通过初筛的文章。

在“设置 → 报告与服务”点击“检查 Jev 连接”，会用一段自编短文验证实际接口和评分格式，不采集真实文章、不生成报告、不发送消息；产生一次 Jev 调用，用量单独记作连接检查。配置已填写不等于已通过检查。

未填写 Jev 密钥或关闭初筛时，只做免费的关键词筛选，再直接调用分析模型；界面明确显示当前情况。有密钥但 Jev 超时、鉴权失败或返回格式不完整时，文章留待重试，不绕过初筛调用昂贵模型，也不伪造低分。

## Jev 怎样减少 DeepSeek 的工作

启用 Jev 且已配置密钥时，后台使用下面的流程；关闭或未配置时保留原来的 DeepSeek 分组与全文分析方式。

1. 程序先匹配关键词，Jev Score 再判断文章是否值得继续处理。初筛仍只读取标题和前 300 字，不生成摘要。
2. 程序从近期已完成事件中，按标题词语选出最多 8 个归类候选。Jev Choice 判断是否围绕同一个具体事件；同一公司、相近主题或不同版本不能直接合并。不确定就新建事件。明确的多主题早报单独处理。候选查找目前仅覆盖最近 48 小时、读取的最近 200 个事件；手动报告还要求旧事件的文章都在本次固定范围内。所有旧来源必须符合当前关键词并已通过当前规则的初筛；更改偏好后尚未重新判断的旧事件不会直接合并。
3. 程序把原文分成不改写文字的编号片段，去掉完全重复的片段。Jev Noul 判断哪些片段包含具体事实、数据、技术细节、实测条件、限制或有依据的不同观点。每次请求最多判断 24 个片段，但会遍历整篇正文；这只是接口请求大小，不是每天或每篇文章的配额。概率至少 0.55 的片段才交给 DeepSeek；首次分析如果全未选中，保留最高值的一段，避免用空输入冒充降本。
4. 新文章归入已有事件后，Jev 将片段与已有摘要、要点、事实和观点比较。没有值得更新的内容就沿用结果、补充原文链接，不再次调用 DeepSeek。完全相同正文由程序直接识别，不重复作归类和新增信息判断。未深入分析的文章不伪造质量评分。
5. 有重要新增内容时，DeepSeek 只收到新片段、已有结论和一篇代表文章的旧引文，不收到全部历史正文。它更新完整摘要和阅读建议，程序保留旧事实的原文出处，并标为“此前报道”。纠正或冲突应在不确定事项中说明；尚未实现对旧事实逐条撤销或判定真伪。

文章全文仍保存。DeepSeek 只能引用实际发送的片段编号；服务器从原文取回引文，并检查来源与编号对应关系。报告注明未阅读全文，质量和夸张程度仅针对片段，不宣称已经完整核查所有来源。Jev 不生成摘要，也不核实事实。筛选可能遗漏细节、营销表述或较弱的新观点。

归类与片段判断缓存包含模型版本、问题、文章内容和已有分析背景；相同输入可以复用。失败不缓存、不绕过 Jev 调用昂贵模型，更新失败保留旧报告，新文章继续等待处理。手动拆分清除旧分析和片段范围。

原有单次任务的时间与容量限制仍保留：每次读取最多 60 篇待处理文章，初筛最多 12 篇没有缓存的文章，`deepLimit` 控制每次继续处理的数量，手动操作最多连续执行三次。它们没有变成每日 Token 预算，也没有作为本次降本的依据。所选片段合计仍有模型输入容量保护；超过容量会保留文章并报错，不冒充已完成。历史事件文章数量增长时，新增内容不会默认触发全部正文重读，但事件 JSON 的存储、候选索引与来源展示仍有后续扩展空间。

## 查看用量与接口

在“设置 → 报告与服务 → 控制 AI 用量”，分别查看要求解析、Jev 阅读价值判断、归类、片段筛选、新增信息判断、DeepSeek 首次与更新分析、格式修复的调用次数，以及服务返回的输入和输出 Token。Jev 读取 `usage.input_tokens/output_tokens`，兼容分析模型读取 `usage.prompt_tokens/completion_tokens`。服务未返回有效统计、连接失败或未知结果都标为用量未知，不计作零。统计仅覆盖本次更新后的后台调用，保留 30 天；不保存密钥、正文或请求内容，不换算成未经确认的费用。

- `GET /api/automation` 返回当前 `policy`、Jev 配置是否填写和最近 24 小时 `usage`。
- `POST /api/automation/screening/check` 只检查 Jev 连接，需要空 JSON 对象 `{}`；与后台任务共用任务锁。
- `POST /api/automation/policy/parse` 接收 `{instruction}`，只返回解析后的关键词和方法。
- `PATCH /api/automation/policy` 保存完整对象：`instruction`、`include`、`exclude`、`screenEnabled`、`minValue`、`deepLimit`。关注和排除各最多 20 个词，每个最多 60 字，输入句子最多 500 字。

接口继续要求管理口令，写请求要求同源；保存规则与后台任务共用任务锁。D1 新增 `collection_policy`、`article_screenings`、`model_usage` 三张表，不修改旧文章、推送配置或历史报告。
