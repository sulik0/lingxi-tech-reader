# 实现说明

前端围绕聚合报告：`app/page.tsx` 挂载报告工作台，`components/automation-panel.tsx` 负责连接、检索、生成、推送和设置，`components/report-body.tsx` 渲染报告及原文链接。操作步骤和接口见[自动订阅](automation.md#手动检索生成报告和推送飞书)。本文维护共享分析接口与结果规则。

原始文章列表、手动导入、收藏、已读和导出不再有前端入口。旧浏览器数据没有删除；当前页面不读取或写入这些数据。真实文章、事件、报告与发送记录保存在 D1，刷新后重新连接即可读取。

## 分析接口

`build/sites-worker.ts` 直接处理两个路径，再调用 `lib/analyze.ts`。这些接口不通过 `app/api/` 路由实现。

- `GET /api/status`：返回 `configured` 和 `collectionConnected`，含义见[配置说明](configuration.md#怎样确认配置生效)。当前状态路径没有额外限制 HTTP 方法。
- `POST /api/analyze`：接受 `{"articles": [...]}`。请求必须带与请求 URL 的 Origin 完全相同的 `Origin` 头，以及包含 `application/json` 的 `Content-Type`。

所有接口响应均为 JSON，带 `Cache-Control: private, no-store`。同源检查不等于用户鉴权；线上访问控制见[构建与部署](deployment.md#线上运行需要准备什么)。

### 请求字段和大小限制

| 字段或范围 | 当前校验 |
| --- | --- |
| `articles` | 1–12 篇。 |
| `id` | 非空字符串，最多 80 个字符，本次请求内唯一。 |
| `title` | 去掉首尾空白后不能为空，原字符串最多 160 个字符。 |
| `source` | 去掉首尾空白后不能为空，原字符串最多 60 个字符。 |
| `content` | 每篇 80–16,000 个字符，合计最多 72,000 个字符。 |
| `author` | 可选；字符串截取前 80 个字符，非字符串时使用“未提供”。 |
| HTTP 正文 | 若声明的 `Content-Length` 大于 350,000 则拒绝；读入后的请求字符串长度大于 160,000 也拒绝。前者按 HTTP 字节长度，后者按 JavaScript 字符串长度检查。 |

分析接口接受 ID、标题、来源、正文和作者，不要求原文 URL。接口支持一篇文章，但无法据此可靠地判断相对原创度或重复度。

### 模型调用

Worker 用服务端环境变量构造请求，兼容要求和参数见[配置说明](configuration.md#模型服务需要支持什么)。调用使用 `AbortSignal.timeout(55000)`，超过 55 秒中止。格式或证据校验失败最多重新请求一次；连接错误不自动重试。共享分析接口不联网查询；自动文章由后台队列继续处理，见[自动订阅](automation.md#去重分组和分析)。

模型提示词要求只比较输入文章，把正文中的指令当作不可信内容，不凭记忆补充事实。模型返回的外层响应最多允许 180,000 个字符，`choices[0].message.content` 最多 80,000 个字符，随后解析其中的 JSON 并检查结果。

### 结果检查

普通事件必须确认 `sameEvent: true`。多篇不同事件返回 422，需要通过后台接口修正分组；单篇综合早报使用 `articleKind: "roundup"`、`sameEvent: false`，仍需完整分析。缺少确认则拒绝结果。成功响应中的 `result` 包含 `articleKind`、`recommendedArticleId` 以及 `title`、`summary`、`points`、`facts`、`opinions`、`evaluations`、`conclusion` 和 `uncertainty`。

| 内容 | 服务端要求 |
| --- | --- |
| 摘要与要点 | 标题最多 160、摘要最多 1,800 个字符；要点最多 10 条，每条最多 1,000 个字符。 |
| 事实 | 最多 18 条。每条包含 `text`、`status`、`sources`、`evidence`；陈述最多 900 个字符，来源为输入文章的有效且不重复的 ID，至少一个、最多 12 个。 |
| 事实状态 | 只允许“来源一致”或“待核验”。“来源一致”至少引用两篇文章，禁止真实分析返回“已核验”。 |
| 引用原句 | `evidence` 只允许空白和明确 HTML 字符编码差异，随后恢复成至少一篇引用正文的连续原句；不容许改写或拼接。提示词要求最多 600 个字符，代码实际允许最多 1,600 个字符。 |
| 观点 | 最多 18 条，来源名称必须存在于输入。作者最多 80 个字符，观点和判断依据各最多 900 个字符。 |
| 逐篇评价 | 每篇文章恰好一条，文章 ID 不重复；四项指标与重复度必须为 0–100 的有限数值，服务端四舍五入。夸张程度只能为“低”“中”“高”。 |
| 推荐理由与夸张说明 | 理由最多 900、新增信息说明最多 500 个字符；夸张说明最多 6 条，每条最多 500 个字符。 |
| 阅读建议与不确定事项 | 两项都必须填写，各最多 1,200 个字符。 |

这些检查能发现缺字段、错误 ID、无依据的核验标签和不存在的引文。程序只检查原句出现在某一篇引用正文中，不检查每篇来源是否都支持同一个说法，不验证来源是否独立，也不验证观点作者身份、引文与结论之间的逻辑或外部真实性。多篇文章说法一致，仍可能是同源转载。

### 评分与推荐

模型给出四项指标，服务端按下式计算并四舍五入为综合分：

```text
综合分 = 信息密度 × 30% + 原创度 × 25% + 事实性 × 25% + 分析深度 × 20%
```

原创度和重复度只针对本次提交的文章，不能说明是不是全网首发。优先使用模型返回的有效推荐文章 ID；兼容旧结果时才选择有评分文章中综合分最高的一篇。推荐理由需要说明这篇文章提供了什么信息。

重复度按 `duplicate >= 75` 判断，不删除文章。主页只展示聚合报告，各篇评价在分析依据中展开查看。

### 响应与错误

成功返回 `{"result": {...}}`；失败返回 `{"message": "原因"}`，不保存虚构的替代结果。

| HTTP 状态 | 原因 |
| --- | --- |
| 400 | JSON 无法解析，文章字段、数量或正文长度不符合要求。 |
| 403 | Origin 缺失或与请求地址不同。 |
| 405 | 分析接口使用了 POST 以外的方法。 |
| 413 | HTTP 请求大小超过限制。 |
| 415 | Content-Type 不包含 `application/json`。 |
| 422 | 模型判断文章讨论的是不同事件。 |
| 503 | 模型变量未配齐或基础地址无效。 |
| 502 | 模型服务连接失败、超时、响应错误或结果未通过检查。服务商返回 429 时，应用显示额度或请求过多的提示，但仍返回 502。 |
| 500 | 未预期的程序错误。 |

具体排查步骤见[常见问题](troubleshooting.md#界面显示-ai-已连接但分析失败)。

## 已知实现限制

- 检索范围是已配置订阅源，不是全网关键词搜索；公众号需另行接入订阅服务。
- 每轮容量有限，未完成部分明确提示，数值规则见[自动订阅](automation.md)。
- 原始文章只提供链接，不抓取链接补齐全文，不做外部事实核查。
- 分组修正和重新分析接口保留，前端当前不提供文章管理入口。
- 不实现多用户、跨设备收藏、历史浏览器数据恢复或报告内关键词检索。
