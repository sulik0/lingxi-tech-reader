# 实现说明

本文说明当前代码的实际行为。演示事件来自 `lib/data.ts`；工作台的导入和本地操作在 `app/page.tsx`；分析规则在 `lib/analyze.ts`。演示包含 6 个虚构事件、24 篇虚构文章和预先写好的评分，不是实时科技资讯。

## 导入、去重与分组

导入表单要求标题、来源和正文，允许填写 HTTPS 原文链接。标题最多 160 个字符，来源最多 60 个字符，链接最多 1,500 个字符；正文去掉首尾空白后至少 80 个字符，导入前检查的原始正文最多 16,000 个字符。本文的字符串长度均按 JavaScript `.length` 计算，即 UTF-16 code unit 数量，不是 token 数量，也不等于所有情况下的汉字数。

浏览器为文章生成 UUID。当前表单没有独立作者字段，文章的 `author` 固定为“未提供”；需要保留作者信息时可写在正文中。原文链接不会被打开或抓取。浏览器最多保留 40 篇自定义文章，演示文章不计入这个数量。

去重只检查已导入文章的正文是否完全相同：保存前删去首尾空白，随后直接比较字符串。程序不清理 HTML、菜单或广告，不统一正文内部空白，也不按 URL、正文指纹或语义相似度去重。

初步分组只比较同一分类下的自定义事件，不把导入文章并入演示事件。具体步骤是：

1. 将新文章标题与已有事件标题转成小写，提取长度至少为 3 的英文、数字及点号和连字符组合；连续中文片段按相邻两个字切分。
2. 将这些片段放入集合，计算交集大小除以并集大小的 Jaccard 相似度。
3. 如果两个标题都包含英文字母开头的词，要求至少有一个这样的词完全相同。这只是字符串检查，不是实体识别。
4. 从已有事件中选择第一个分类相同且相似度至少为 0.32 的事件；没有匹配时创建新事件。程序不选择所有候选中相似度最高的事件。

新事件标为 `pending: true`，显示正文开头的截取片段，不自动调用模型。向已有事件加入文章时，会移除旧文章评价，清空综合要点、事实和观点，标记待重新分析。多篇文章的事件支持把单篇拆成新事件；拆分后的两个事件也需要重新分析。

## 保存与导出

`localStorage` 的键为 `lingxi-workspace-v1`，保存对象包含 `saved`、`read`、`subscriptions`、`custom` 和 `hideDemo`。页面加载时恢复数据，状态变化时写回。恢复过程只有基本字段检查，没有完整数据校验和版本迁移。

文章、分析结果、收藏、阅读记录和来源开关都保存在当前浏览器的当前 Origin 下；手动导入的数据没有服务端副本，也没有账号或跨设备同步。自动订阅保存到独立的 D1 表，见[自动订阅与推送](automation.md)。写入失败会提示本次改动无法保存。

设置中的 JSON 导出包含上述字段，并增加 `version: 1` 和 `exportedAt`。它是供留存和后续处理的数据文件，目前没有导回或恢复界面。阅读室的 Markdown 导出包含摘要、综合要点、事实原句与来源、观点、推荐文章和不确定事项；它不是完整的文章库导出。

## 分析接口

`build/sites-worker.ts` 直接处理两个路径，再调用 `lib/analyze.ts`。这些接口不通过 `app/api/` 路由实现。

- `GET /api/status`：返回 `configured` 和 `collectionConnected`，含义见[配置说明](configuration.md#怎样确认配置生效)。当前状态路径没有额外限制 HTTP 方法。
- `POST /api/analyze`：接受 `{"articles": [...]}`。请求必须带与请求 URL 的 Origin 完全相同的 `Origin` 头，以及包含 `application/json` 的 `Content-Type`。

所有接口响应均为 JSON，带 `Cache-Control: private, no-store`。同源检查不等于用户鉴权；线上访问控制见[构建与部署](deployment.md#线上运行需要准备什么)。

### 请求字段和大小限制

| 字段或范围 | 当前校验 |
| --- | --- |
| `articles` | 1–12 篇。 |
| `id` | 非空字符串，最多 80 个字符，本次请求内唯一。 |
| `title` | 去掉首尾空白后不能为空，原字符串最多 160 个字符。 |
| `source` | 去掉首尾空白后不能为空，原字符串最多 60 个字符。 |
| `content` | 每篇 80–16,000 个字符，合计最多 72,000 个字符。 |
| `author` | 可选；字符串截取前 80 个字符，非字符串时使用“未提供”。 |
| HTTP 正文 | 若声明的 `Content-Length` 大于 350,000 则拒绝；读入后的请求字符串长度大于 160,000 也拒绝。前者按 HTTP 字节长度，后者按 JavaScript 字符串长度检查。 |

浏览器提交 ID、标题、来源、正文和作者，不提交原文 URL。接口支持一篇文章，但无法据此可靠地判断相对原创度或重复度。

### 模型调用

Worker 用服务端环境变量构造请求，兼容要求和参数见[配置说明](configuration.md#模型服务需要支持什么)。调用使用 `AbortSignal.timeout(55000)`，超过 55 秒中止，没有自动重试、外部查询或后台队列。

模型提示词要求只比较输入文章，把正文中的指令当作不可信内容，不凭记忆补充事实。模型返回的外层响应最多允许 180,000 个字符，`choices[0].message.content` 最多 80,000 个字符，随后解析其中的 JSON 并检查结果。

### 结果检查

模型必须确认 `sameEvent: true`。若为 `false`，接口返回 422，要求用户拆分；缺少确认则拒绝结果。成功响应中的 `result` 包含 `title`、`summary`、`points`、`facts`、`opinions`、`evaluations`、`conclusion` 和 `uncertainty`。

| 内容 | 服务端要求 |
| --- | --- |
| 摘要与要点 | 标题最多 160、摘要最多 1,800 个字符；要点最多 10 条，每条最多 1,000 个字符。 |
| 事实 | 最多 18 条。每条包含 `text`、`status`、`sources`、`evidence`；陈述最多 900 个字符，来源为输入文章的有效且不重复的 ID，至少一个、最多 12 个。 |
| 事实状态 | 只允许“来源一致”或“待核验”。“来源一致”至少引用两篇文章，禁止真实分析返回“已核验”。 |
| 引用原句 | `evidence` 必须作为连续字符串出现在至少一篇被引用文章的正文中。提示词要求最多 600 个字符，代码实际允许最多 1,600 个字符。 |
| 观点 | 最多 18 条，来源名称必须存在于输入。作者最多 80 个字符，观点和判断依据各最多 900 个字符。 |
| 逐篇评价 | 每篇文章恰好一条，文章 ID 不重复；四项指标与重复度必须为 0–100 的有限数值，服务端四舍五入。夸张程度只能为“低”“中”“高”。 |
| 推荐理由与夸张说明 | 理由最多 900、新增信息说明最多 500 个字符；夸张说明最多 6 条，每条最多 500 个字符。 |
| 阅读建议与不确定事项 | 两项都必须填写，各最多 1,200 个字符。 |

这些检查能发现缺字段、错误 ID、无依据的核验标签和不存在的引文。程序只检查原句出现在某一篇引用正文中，不检查每篇来源是否都支持同一个说法，不验证来源是否独立，也不验证观点作者身份、引文与结论之间的逻辑或外部真实性。多篇文章说法一致，仍可能是同源转载。

### 评分与推荐

模型给出四项指标，服务端按下式计算并四舍五入为综合分：

```text
综合分 = 信息密度 × 30% + 原创度 × 25% + 事实性 × 25% + 分析深度 × 20%
```

原创度和重复度只针对本次提交的文章，不能说明是不是全网首发。浏览器选择有评分文章中综合分最高的一篇；同分时保留原有顺序。模型另外生成的 `conclusion` 是阅读建议，可能与按分数选出的推荐不完全一致。

“识别重复”的统计按 `duplicate >= 75` 计数，不删除文章。“预计节省”按每篇 5 分钟减去事件阅读分钟数估算，最低显示 0；不是对真实阅读时间的测量。

### 响应与错误

成功返回 `{"result": {...}}`；失败返回 `{"message": "原因"}`，不保存虚构的替代结果。

| HTTP 状态 | 原因 |
| --- | --- |
| 400 | JSON 无法解析，文章字段、数量或正文长度不符合要求。 |
| 403 | Origin 缺失或与请求地址不同。 |
| 405 | 分析接口使用了 POST 以外的方法。 |
| 413 | HTTP 请求大小超过限制。 |
| 415 | Content-Type 不包含 `application/json`。 |
| 422 | 模型判断文章讨论的是不同事件。 |
| 503 | 模型变量未配齐或基础地址无效。 |
| 502 | 模型服务连接失败、超时、响应错误或结果未通过检查。服务商返回 429 时，应用显示额度或请求过多的提示，但仍返回 502。 |
| 500 | 未预期的程序错误。 |

具体排查步骤见[常见问题](troubleshooting.md#界面显示-ai-已连接但分析失败)。

## 已知实现限制

以下行为尚未修复，维护或使用时需要留意：

- **来源筛选会影响重新分析。** 工作台先移除停用来源的文章，再把显示中的事件传给分析。分析成功后，用这份文章集合覆盖原事件，隐藏文章可能从事件中丢失；拆分操作也使用当前显示集合。分析或拆分前应启用全部相关来源并导出 JSON。旧简报的事实和观点也不会随来源开关重新计算。
- **待分析事件可能保留旧建议。** 添加文章或拆分时，程序清空评分、事实、观点和要点，但仍保留原 `conclusion` 和 `uncertainty`。重新分析成功前，不应把这些文字当成新分组的结论；Markdown 导出也可能带上这些旧内容。
- **日期和时间尚未按真实发布时间管理。** “今天”只排除 `time` 等于“昨天”的事件，导入事件始终标为“刚刚”，没有保存完整发布时间。演示时间、侧栏日期和今日简报日期是固定展示文字，不是自动生成的每日资讯。
- **最新排序沿用数组顺序。** 它没有比较时间戳；刷新按钮也只更新时间提示，不采集新文章。
- **没有文章删除、任意合并或 JSON 恢复界面。** 导入上限、备份和重置操作的处理方式见[常见问题](troubleshooting.md#导入达到上限后怎样清理)。
