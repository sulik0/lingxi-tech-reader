# 测试与验证

## 本地检查

使用[配置说明](configuration.md#开发环境)中的 Node.js 版本并安装依赖后，执行：

```sh
npm run typecheck
npm test
npm run build
```

三条命令分别检查 TypeScript、运行 Node.js 内置测试和生成 Worker 构建产物。`npm run lint` 也有定义，但不属于当前 GitHub Actions 的检查步骤。

仅改文档时，检查 Markdown 链接、命令和代码描述，再执行 `git diff --check` 并阅读差异即可。无需为了文档改动增加镜像实现逻辑的测试。

## 自动测试覆盖了什么

`tests/analysis.test.mjs` 包含模型结果和调用规则的测试，直接导入 `lib/analyze.ts`：

- 拒绝重复文章 ID、过短正文和过多文章。
- 根据四项指标计算综合分，并保留正文中的原句。
- 拒绝不存在的来源、无依据的“已核验”状态、找不到的原句、仅引用一篇的“来源一致”，以及重复的文章评价。
- 模型判断文章属于不同事件时，返回可拆分事件的错误。
- 未配置服务时返回错误，不伪造分析结果。
- 拒绝不同源请求，检查未配置服务的响应和禁止缓存的响应头。
- 使用模拟模型响应检查调用地址、鉴权格式和结果解析，并隐藏模型服务的原始错误内容。

这些测试不需要真实密钥，不调用外部模型。它们没有证明文章分组准确、评分客观、模型服务可用、界面交互完整或自动采集已经实现。字段长度等规则也没有逐项覆盖所有边界；完整约束见[实现说明](implementation.md)。

自动订阅测试位于 `tests/automation.test.mjs`，使用内存 SQLite 执行实际迁移和查询，通过模拟 HTTP 验证 RSS/Atom、来源地址限制、北京时间、去重、任务锁、事件分组、三渠道协议、重复执行、预览不发送、失败和超时。测试使用自编文章和假密钥，不向外部渠道发送消息。

## 浏览器验证前端

按[前端设计的验收标准](DESIGN.md#确认后的实施与验收)检查页面；开发过程使用 `frontend-design`、React 实现规范与 `web-design-guidelines` 审查。类型检查和构建不能替代实际交互。

1. 连接后浏览已分析资讯，检查原文发布时间排序、来源链接、摘要展开和待处理提示；刷新失败应保留旧列表。
2. 输入“不看汽车手机，多看 AI Agent”，先检查解析预览，确认之前不写策略；保存与反馈不调用采集、生成或发送接口。检查取消、修改输入、解析失败、保存失败与后台忙状态。
3. 收藏、取消、浏览器刷新恢复，以及存储失败。新收藏只存 ID；改变偏好隐藏收藏时，不删除记录。
4. 设置弹窗检查飞书与企业微信的真实记录，保存时保留邮件配置；检查当前等待报告不会沿用历史可发送状态，送达不明不能重发。
5. 在 1440、1024、768、390、320px 检查长标题、来源和偏好，确认无横向溢出；验证弹窗焦点、Escape、关闭后的焦点返回与减少动态效果。
6. 检查控制台及页面异常。刻意模拟的 401/409/502/503 请求应有对应提示，不能把这些网络错误误记成未处理的页面错误，也不能忽略其他异常。

使用 Playwright CLI 技能启动独立本地浏览器。自编响应仅用于 UI 验收，不证明真实模型质量或群消息送达；不向真实群发送测试消息。截图放在被 Git 忽略的 `output/playwright/`，CLI 会话文件也不提交。具体完成记录见[阶段验收](acceptance.md)。

## GitHub Actions

`.github/workflows/ci.yml` 在推送 `main` 和创建或更新 PR 时执行。它使用 Node.js 24，依次运行 `npm run install:ci`、`npm run typecheck`、`npm test` 和 `npm run build`。整个任务最多运行 15 分钟，同一分支的新运行会取消较旧的运行。

检查结果见仓库的 [Actions 页面](https://github.com/sulik0/lingxi-tech-reader/actions)。本地修改完成后，按 [AGENTS.md](../AGENTS.md)检查差异、提交并推送；工作流成功不代表站点已经部署或真实模型已接通。

## 真实来源和模型验证

执行[自动订阅](automation.md#部署和验收)中的验收脚本。它将真实正文、SQLite 和事件写入忽略的 work 目录，并报告来源成功、失败、重复入库、模型配置和成功分析数。无凭据不输出假分析。curl 路径只能证明本机网络，不代替 Worker 验收。

真实聚类质量需要人工标注案例后重新运行；结构校验通过不代表聚类或推荐准确。回归案例使用方法见[质量验证](quality.md)。

分析失败的回归测试还检查：超过要点上限时向重试提供实际字段和数量；截断的 JSON 最多重试一次；恢复空白和 HTML 字符编码后，引文仍必须是正文连续片段；改动数字或拼接不同段落继续拒绝；综合早报单独分组并在机器人简报保留多主题说明。后台手动重分析会向页面返回具体分析错误，失败时保留待分析文章。

简报回归检查覆盖：本轮收集的文章能进入当天简报；空内容不发送且同日可恢复；待分析不是生成失败；预览不发送、不消耗正式队列；部分完成时只纳入真实通过校验的文章，失败文章仍排队；旧空简报只允许一份有内容的补充；渠道失败和送达不明不显示成功；预览历史不会覆盖正式记录。迁移测试检查新增统计字段不改变旧正文和设置。

报告回归另检查采集、生成、发送各自的调用范围，发送固定正文、暂停每日任务时主动发送、空内容与超期拒绝、互斥锁、送达不明不重试、新接口鉴权和 URL 编码。固定范围测试检查同一编号逐批完成、旧积压和中途新增不占本次范围、已完成结果复用、处理中保存真实阶段、初筛失败停止且恢复后可继续、变更偏好及发送后不能改写；进度接口不返回原文、报告正文或范围编号。

前端辅助逻辑由 `tests/client-feed.test.mjs` 检查：真实时间排序、排除待分析与演示事件、整组关键词筛选、收藏随分组变化恢复、取消收藏、安全链接、偏好变更比较及预算保留。浏览器检查范围和限制见上文。

搜集策略测试覆盖否定解析、主题词、排除优先、Jev 官方请求格式、低把握保留、缓存与版本变化、每轮预算、初筛失败不调用完整分析、已完成事件复用、同源配置接口与缺失用量统计。使用自编正文和模拟模型响应，不代表真实 Jev 密钥或判断质量已经验收。
