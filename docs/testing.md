# 测试与验证

## 本地检查

使用[配置说明](configuration.md#开发环境)中的 Node.js 版本并安装依赖后，执行：

```sh
npm run typecheck
npm test
npm run build
```

三条命令分别检查 TypeScript、运行 Node.js 内置测试和生成 Worker 构建产物。`npm run lint` 也有定义，但不属于当前 GitHub Actions 的检查步骤。

仅改文档时，检查 Markdown 链接、命令和代码描述，再执行 `git diff --check` 并阅读差异即可。无需为了文档改动增加镜像实现逻辑的测试。

## 自动测试覆盖了什么

`tests/analysis.test.mjs` 当前包含 7 个测试，直接导入 `lib/analyze.ts`：

- 拒绝重复文章 ID、过短正文和过多文章。
- 根据四项指标计算综合分，并保留正文中的原句。
- 拒绝不存在的来源、无依据的“已核验”状态、找不到的原句、仅引用一篇的“来源一致”，以及重复的文章评价。
- 模型判断文章属于不同事件时，返回可拆分事件的错误。
- 未配置服务时返回错误，不伪造分析结果。
- 拒绝不同源请求，检查未配置服务的响应和禁止缓存的响应头。
- 使用模拟模型响应检查调用地址、鉴权格式和结果解析，并隐藏模型服务的原始错误内容。

这些测试不需要真实密钥，不调用外部模型。它们没有证明文章分组准确、评分客观、模型服务可用、界面交互完整或自动采集已经实现。字段长度等规则也没有逐项覆盖所有边界；完整约束见[实现说明](implementation.md)。

自动订阅测试位于 `tests/automation.test.mjs`，使用内存 SQLite 执行实际迁移和查询，通过模拟 HTTP 验证 RSS/Atom、来源地址限制、北京时间、去重、任务锁、事件分组、三渠道协议、重复执行、预览不发送、失败和超时。测试使用自编文章和假密钥，不向外部渠道发送消息。

## 手动验证阅读流程

涉及界面、导入或本地保存的改动时，至少按受影响的流程验证：

1. 打开演示工作台，检查事件列表、筛选、阅读室、收藏和已读状态；刷新后确认保存结果。
2. 用自编或允许处理的正文导入文章；分别尝试相同正文、标题相近和标题无关的文章，检查分组。误分时从文章预览拆出独立事件。
3. 不配置模型时点击分析，确认显示原因且文章仍在。配置服务后再检查成功结果、引用、评分、推荐和导出。
4. 在设置中隐藏演示内容、导出 JSON，再导出一个事件的 Markdown 简报，确认内容和来源对应。
5. 涉及弹窗时检查键盘焦点、Escape 关闭和小屏布局。

分析前启用该事件的全部来源；当前来源筛选的实现限制见[已知实现限制](implementation.md#已知实现限制)。不要把真实正文、浏览器导出的 JSON 或模型密钥放进测试夹具和 Git 提交。

## GitHub Actions

`.github/workflows/ci.yml` 在推送 `main` 和创建或更新 PR 时执行。它使用 Node.js 24，依次运行 `npm run install:ci`、`npm run typecheck`、`npm test` 和 `npm run build`。整个任务最多运行 15 分钟，同一分支的新运行会取消较旧的运行。

检查结果见仓库的 [Actions 页面](https://github.com/sulik0/lingxi-tech-reader/actions)。本地修改完成后，按 [AGENTS.md](../AGENTS.md)检查差异、提交并推送；工作流成功不代表站点已经部署或真实模型已接通。
