# 自动订阅与每日推送

当前版本支持单管理员配置 RSS/Atom 来源，后台每 15 分钟检查新文章，再按北京时间生成每日简报。邮件、企业微信和飞书可以同时启用。功能代码已实现，但需要实际部署、模型和发送服务配置后才会持续运行；本地开发服务不会自己定时触发。

## 指定公众号和试用来源

在“订阅管理 → 自动订阅与每日推送”中输入管理口令，添加来源名称和 RSS/Atom 地址。来源名用于显示，地址才是后台获取文章的入口。原来的来源卡片仍只用于筛选手动导入的文章，两者分别管理。

没有公众号文章服务时，可以先试用以下公开网站订阅。它们不代表已经读取了用户的微信关注列表：

| 来源 | 订阅地址 | 本次检查 |
| --- | --- | --- |
| 极客公园 | `https://www.geekpark.net/rss` | HTTP 200，已用于解析验证。 |
| 宝玉的分享 | `https://baoyu.io/feed.xml` | HTTP 200，仅提供短摘要；本次最新条目日期为 2026-09-19。 |
| 量子位 | `https://www.qbitai.com/feed` | 本机请求返回 403，保留为候选，不能当作已接通。 |

上述结果只反映 2026-10-09 的检查，不保证长期可用。仅把地址预填进表单不会开始采集，添加并启用后才会读取。应用不绕过来源的登录或访问限制。

如需监听指定公众号，可以自己部署 [WeWe RSS](https://github.com/cooderl/wewe-rss)，按该项目步骤授权账号并添加公众号，然后把生成的订阅地址填到灵析。该服务支持输出 RSS/Atom；灵析不保存微信登录凭据，也不代替用户扫码授权。Worker 只接受可访问的 HTTPS 来源，需要把你部署服务的确切域名加入允许列表。

## 初始化本地后台

使用现有开发环境，执行：

```sh
cp .env.example .dev.vars
npm run db:migrate
npm run dev
```

如果已有 `.dev.vars`，请直接编辑它，避免覆盖已有密钥。在文件中设置 `AUTOMATION_TOKEN`，至少 24 个字符；例如可用 `openssl rand -hex 24` 生成口令。把这个口令输入管理界面，它只保留在本次页面内存中，退出管理或刷新后需要重新输入。

`npm run db:migrate` 按 `migrations/0001_automation.sql` 初始化本地 D1，使用 `.wrangler/state` 保存数据。`wrangler.local.jsonc` 只用于本地迁移，数据库 ID 是本地占位值，不用于线上部署。

## 配置服务和渠道

模型配置沿用[配置说明](configuration.md#本地模型配置)。自动订阅另外读取下列服务端变量：

| 变量 | 用途 |
| --- | --- |
| `AUTOMATION_TOKEN` | 单管理员口令，至少 24 个字符。所有管理接口都要求 Bearer 鉴权，修改操作还检查 Origin。 |
| `FEED_ALLOWED_HOSTS` | 允许获取的确切域名，用逗号分隔；示例文件包含上表三个域名。添加自己部署的公众号服务时追加其域名。 |
| `RESEND_API_KEY` | 邮件服务密钥。 |
| `EMAIL_FROM` | Resend 已授权发信域名下的发件人地址。 |
| `WECOM_WEBHOOK_URL` | 企业微信群机器人完整 Webhook 地址。 |
| `FEISHU_WEBHOOK_URL` | 飞书群机器人完整 Webhook 地址。 |
| `FEISHU_SIGNING_SECRET` | 飞书机器人开启签名校验时填写的密钥；未开启时可以留空。 |

订阅地址不能包含账号密码，必须使用 HTTPS 和已允许的域名。订阅请求拒绝 IP 地址、非标准端口和重定向，避免误读其他服务；发生重定向时应填写最终地址。允许域名应由管理员核对，不要允许不受信任的域名。

邮件使用 [Resend 发送接口](https://resend.com/docs/api-reference/emails/send-email)。企业微信使用[群机器人接口](https://developer.work.weixin.qq.com/document/path/91770)，飞书使用[自定义机器人接口](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。配置机器人时，还要让关键词、IP 限制和签名要求与当前部署相符。

界面只保存收件邮箱、渠道开关和发送时间，邮件密钥、机器人地址和签名密钥不返回浏览器。显示“配置已填写”不代表真实发送已验证。保存设置后，可以先生成预览，再启用每日推送；真实收件地址和渠道仍需要由用户填写。

## 每日怎样处理

1. 读取启用的来源。每个来源最多处理订阅中的前 50 条，接收最近 48 小时的文章，拒绝超过 2 MB 的订阅内容。正文删去 HTML 标签，最多保留 16,000 个 JavaScript 字符；来源只提供摘要时，不会另外抓取原文补全。
2. 按来源和文章 ID、原文地址避免重复入库。每天生成时，再按忽略空白后的正文哈希排除完全相同的正文。
3. 到设置的时间后，处理“前一天发送时间至当天发送时间”的文章。以首次正式生成的正文为当天固定简报；后续重试使用同一份内容。发布时间缺失时使用首次读取时间，延迟出现且已超出窗口的文章可能不会进入当天简报。
4. 一次读取最多 241 条，分析最多 24 篇不同文章，优先选择较新的文章；简报明确提示达到上限或有未处理文章。模型先按事件分组，要求每篇恰好出现一次，再调用现有分析模块。分析请求最多三个并行，单组正文超过服务限制时拆成批次。
5. 只有不足 80 字摘要的文章保留标题、摘要和链接，不虚构评分。模型或引用检查失败时，简报标为生成失败，本次不发送；下次定时检查可重新尝试。部分来源失败时生成的简报会说明缺失范围，全部来源失败时不发“无新闻”的成功简报。
6. 分别发送已选择的渠道，并保存每个渠道的结果。暂停每日推送后，后台仍检查启用的来源；暂停某个来源后不再采集该来源。

“检查新文章”只收集，不生成或发送。“生成预览”使用操作时刻之前的 24 小时，不发送，也不占用当天正式推送。“运行今日任务”按已保存的开关和发送时间执行，不提前发送。

邮件发送完整文本。机器人消息受平台大小限制，发送事件概览和推荐链接，超出限制时提示在应用查看完整简报；企业微信文本控制在 1,900 UTF-8 字节，飞书在 15,000 字节以内。

## 重复任务和失败如何处理

D1 的任务锁防止同时处理，锁在异常退出后最多保留 12 分钟。每日简报使用北京时间日期作为唯一 ID，已成功渠道不会再次发送。

邮件保存第一次生成的发送请求，并使用固定 Idempotency-Key（重复请求编号）。[Resend 的编号有效期为 24 小时](https://resend.com/docs/dashboard/emails/idempotency-keys)，因此应用只在简报创建后 23 小时内重试，每个渠道最多尝试三次，自动重试只在当天定时任务中执行。机器人没有相同的保证：超时、服务端错误或进程中断后标为“无法确认送达”，不自动重试；管理员应先检查群消息。

生成失败、渠道未配置、渠道拒绝和无法确认送达分别显示在界面。发送成功只表示服务接口接收成功，不证明邮件到达收件箱或用户已阅读。修改正式简报发送设置不会改写已经保存的邮件请求；新的设置从后续简报生效。自动采集正文保留 14 天，预览保留 7 天；历史正式简报和发送记录暂不自动删除。

## 部署后台任务

项目包含 Worker `scheduled` 入口和 `*/15 * * * *` Cron Trigger（定时触发器）。[Cloudflare 定时任务使用 UTC](https://developers.cloudflare.com/workers/configuration/cron-triggers/)，代码会换算成北京时间判断用户设置的发送时间。

实际部署前，需要在目标 Cloudflare 账号创建 D1，记录真实数据库 ID；构建时通过环境变量替换占位值：

```sh
LINGXI_D1_DATABASE_ID=实际数据库UUID npm run build
```

然后对构建配置指定的线上数据库执行迁移：

```sh
npx wrangler d1 migrations apply DB --remote --config dist/server/wrangler.json
```

发布操作和密钥设置由已选的托管平台执行，通用构建步骤见[构建与部署](deployment.md)。确认部署后的配置含正确 D1 ID 和 Cron Trigger，配置上述服务端变量，并用管理员口令验证来源、预览和发送记录。当前尚未实际部署或连接真实发信渠道。

本地可以手动测试定时入口（只针对本地服务）：

```sh
curl 'http://localhost:5173/cdn-cgi/local/scheduled?format=json'
```

若已有启用的推送设置和真实凭据，这会执行真实发送。只想验证内容时使用界面的“生成预览”。本地普通服务不会每 15 分钟自己运行；持续监听依赖上线后的 Cron Trigger。

本次验证中，直接 HTTP 工具能读取公开 RSS，但本地 Worker 的出站请求失败，管理界面已保留失败记录，不能当作后台采集成功。遇到同样情况，应检查 Worker 所在环境的网络、代理和证书配置；不要为了通过测试关闭 HTTPS 证书检查。

## 当前范围

这是一套单管理员后台，不提供多用户订阅隔离。后台订阅和简报保存到 D1，手动导入文章仍在当前浏览器中，二者尚未合并成同一个事件列表。外部事实核验、微信关注列表读取、历史文章完整补抓和任意文章网页抓取尚未实现。
