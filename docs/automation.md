# 自动订阅与每日推送

## 从哪里开始

正常流程是配置来源、自动采集、阅读事件和接收每日简报。手动正文导入只在订阅管理下作为开发调试工具保留，不是正式数据入口。

本地项目中的 `.dev.vars` 是隐藏文件。Finder 中按 Command + Shift + . 可以显示隐藏文件；也可在编辑器直接打开。已有文件时直接编辑，不要覆盖。填写：

```dotenv
AUTOMATION_TOKEN=至少24字符的随机管理口令
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash
LLM_API_KEY=你的模型密钥
FEED_ALLOWED_HOSTS=www.geekpark.net,www.ithome.com,s.baoyu.io
FEISHU_WEBHOOK_URL=你的飞书机器人完整地址
FEISHU_SIGNING_SECRET=
```

飞书未开启签名校验时，签名密钥留空。DeepSeek 官方目前接受 `deepseek-v4-flash` 这个名称，但说明它由最新 Flash 版本处理；不能据此保证锁定旧版 V4。见[官方接口说明](https://api-docs.deepseek.com/)。项目对 DeepSeek 明确关闭 thinking，避免结构化输出预算被推理占满；其他兼容服务不发送这个厂商参数。

密钥只留在本地文件和托管平台 Secrets，不写入 Git、浏览器代码或文档。线上变量与本地文件相互独立。修改本地变量后重启开发服务；修改线上变量后需要重新部署使其生效。

运行 `npm run db:migrate` 和 `npm run dev`，在订阅管理中输入口令并添加来源。在自动阅读工作台输入同一个口令，后台事件每分钟刷新一次；口令只放在页面内存，刷新后需重新输入。

## 真实来源检查

2026-10-10 北京时间检查：

| 来源 | 地址 | 实际结果 |
| --- | --- | --- |
| 极客公园 | `https://www.geekpark.net/rss` | 本机 curl 读取成功，解析 30 篇，再次入库新增 0 篇。 |
| IT之家 | `https://www.ithome.com/rss/` | 本机 curl 读取成功，解析 50 篇，再次入库新增 0 篇。 |
| 宝玉博客 | `https://s.baoyu.io/feed.xml` | 地址可读取，但本次没有符合最近 14 天条件的文章。原 `baoyu.io/feed.xml` 返回 301，需要使用最终地址。 |

这些是公开网站订阅，不等于微信公众号监听。来源可能变化，应查看实际检查记录。公众号需要另行部署并授权 [WeWe RSS](https://github.com/cooderl/wewe-rss) 等服务，将最终 HTTPS 订阅地址与确切域名加入配置。

地址必须 HTTPS、属于允许域名，不接受 IP、账号密码、非标准端口或重定向。每个来源最多读前 50 条、最近 14 天的条目；订阅最多 2 MB，正文最多 16,000 个 JavaScript 字符。短摘要保留链接但不评分，不自动抓取原文补齐。

来源读取失败时，管理页保留 HTTP 状态或运行环境的网络错误类型与说明；网络错误中的 URL 和凭据会隐藏。先按这些记录区分超时、证书和其他网络问题。本机可以打开的订阅，仍可能无法从部署平台访问，需要单独检查线上结果。

## 去重、分组和分析

- 同一来源的文章 ID、清理后的 URL 或忽略空白的正文相同，不再次入库。去重记录独立保存，清理正文后也不会把历史文章当成新文章。URL 仅删除常见跟踪参数，保留可能决定正文的其他参数。
- 不同来源相同正文保留出处，事件分析时只提交一份正文，其他相同正文标为没有新增信息。高度相似但不完全相同的内容仍由模型比较，不按相似度直接删除。
- 每次处理最多 6 篇待处理文章，并与近期事件中的最多 6 篇文章重新比较；输入包含标题、时间和最多 4,000 字正文摘录。模型必须完整返回文章 ID，同公司不同事件不能强行合并。
- 每组最多 12 篇，分析正文合计最多 72,000 字，最多三个分析请求同时进行。结构校验失败最多重试一次；超限或失败时保留文章，后续重试，不输出替代的虚构分析。失败事件保留待处理状态，并把重试顺序向后移动，让其他文章继续处理；错误分组仍需要修正。
- 事件保存到 D1，工作台与简报都读取这些事件。没有模型时先展示待分析事件；只有短摘要的文章不生成质量评分。
- 模型推荐具体文章 ID，并说明相比其他文章多提供了什么。兼容旧结果时才回退到综合分排序。事实原句必须存在于引用正文；多源重复不能标为独立核实。

阅读室支持把文章拆成独立事件。操作针对完整后台事件，不因界面来源筛选丢文章；清除两个分组的旧评价和建议，保存人工修正，后台不自动再次合并。已有正式简报保持原样。

## 每日处理和发送

定时任务每 15 分钟采集和处理事件。每日推送默认北京时间 08:00，可按 15 分钟调整。暂停推送仍采集；暂停来源不再抓取新文章；删除来源配置保留历史事件。

正式简报选择在当天发送时刻之前采集、尚未纳入任何正式简报的文章，优先处理较早收集的文章。迟到报道和超过每次 24 篇的文章留在队列，后续简报继续处理。简报正文和已纳入文章编号在同一个数据库事务里保存；重复触发使用冻结的正文，不会重新选择文章。未到发送时间不发送。

预览使用最近 24 小时发布时间内的文章，不发送、不消耗正式队列。检查新文章会同时更新事件，不生成简报。来源失败逐个记录，全部来源失败时不发虚假的“没有新闻”简报。分析未成功时不发送带有假评分的结果。

邮件通过 Resend 发送全文，需要 `RESEND_API_KEY`、已验证发件域名的 `EMAIL_FROM` 和收件邮箱。企业微信使用 `WECOM_WEBHOOK_URL`。飞书使用上述变量。三种渠道均保留，当前用户选择飞书作为主渠道。

机器人发送事件概览和推荐原文，分别限制为企业微信 1,900、飞书 15,000 UTF-8 字节。发送状态区分成功、失败和无法确认送达；接口接受不等于用户实际收到，真实验收还要检查群消息。

已成功渠道不会再发。同一邮件请求使用固定 Idempotency-Key，仅在创建后 23 小时内、最多三次重试。机器人超时、服务端错误或进程中断标为无法确认，不盲目自动重发。任务锁最多 12 分钟，异常退出后可恢复。

已进入正式简报的采集正文保留至少 14 天，预览保留 7 天。未发送的文章、事件正文、去重记录、正式简报和发送记录暂不自动删除，长期运行需监控数据库容量。

## 部署和验收

Worker 包含 scheduled 入口与 `*/15 * * * *` Cron 配置，按北京时间判断发送时间。本地普通服务不会自动运行，不能替代线上任务。Sites 发布是否实际启用 Cron 仍需读回平台配置或观察独立触发记录，不能仅凭构建文件认定任务已上线。

本机可以执行真实来源验收：

```sh
node --env-file=.dev.vars scripts/verify-sources.mjs
# 如果 Node 网络不可用，单独检验本机 curl；这不代表 Worker 网络已正常：
node --env-file=.dev.vars scripts/verify-sources.mjs --curl
```

正文、SQLite、事件和简报仅写入忽略的 `work/acceptance/`。报告区分采集成功和真实分析成功。真实模型、实际飞书送达、线上网络与连续多周期运行分别验收，具体记录见[阶段验收](acceptance.md)。

接口 `GET /api/automation/events` 读取事件，`POST /api/automation/events/:id/split` 修正分组，`POST /api/automation/events/:id/analyze` 重新分析；都要求管理口令，写请求还要求同源。当前只面向单管理员，不新增多用户功能。

线上与本地都使用 db/schema.ts 及 drizzle/ 中的迁移，Sites 从 dist/.openai/drizzle 读取迁移。旧 migrations/ 文件保留为已运行本地版本的历史记录，不继续在其中新增迁移。修改表结构后执行 npm run db:generate，检查生成 SQL，再运行本地迁移与验证。

## Sites 的无人值守入口

只有确认站点仅供所有者访问时，才在平台设置 `SITES_PRIVATE_AUTOMATION=1`。私人站点的访问由 Sites 平台先校验，`POST /api/automation/tick` 供平台云任务执行采集、分析和到时发送，不要求在任务提示中保存管理口令。配置管理和事件读取仍要求口令。这个入口仅在明确启用且域名属于 chatgpt.site 时生效；不得在公开站点启用该变量，也不要把它用于没有平台访问控制的自行部署。

第一次后台执行且尚无设置时，初始化允许域名中的公开试用来源，按北京时间 08:00 启用已配置的飞书渠道。只初始化一次；以后暂停发送、删除来源或修改时间不会被后台覆盖。密钥仍由平台 Secrets 提供。

云任务每次运行：读取当前私人站点支持的服务访问凭据；向站点上述入口发送 POST，并只向该站点发送 `OAI-Sites-Authorization: Bearer <服务凭据>`；记录接口结果，并读回 collection_runs、reading_events 和 digest_deliveries 确认数据库状态。凭据不得写入任务提示、仓库或日志。不重新发布源码，不绕过用户暂停，不盲目重发状态不明的机器人消息。

云任务创建成功只表示定时安排已保存；必须另查执行记录。若平台访问返回 Cloudflare 403，应先解决站点入口或托管平台服务访问问题，不能称为无人值守验收通过。

站点云任务最初按每小时保存，从北京时间 2026-10-10 06:00 起安排执行；最近一次平台读回的当前设置为每 5 小时一次。平台拒绝每 15 分钟安排，因为任务最多每小时一次。每日设定时间之后的第一次成功执行才会处理发送，实际时间可能晚至下一次云任务；应用内发送时间不会改变平台任务频率。任务已保存不等于实际触发和处理已成功，当前实测结果见[验收记录](acceptance.md)。
