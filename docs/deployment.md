# 构建与部署

当前源码保存在私人 GitHub 仓库，站点已通过 Sites 发布，仅供所有者访问。GitHub Actions 负责检查和构建；发布另通过 Sites 完成。站点地址与平台运行记录见[阶段验收](acceptance.md)。

## 构建和本地预览

在已安装依赖的项目目录执行：

```sh
npm run build
npm start
```

构建会生成 `dist/client/` 中的浏览器资源，以及 `dist/server/` 中的 Worker 和 `wrangler.json`。`npm start` 使用这个配置启动本地 Wrangler，监听 `127.0.0.1`；打开终端打印的地址。它不会把网站上传到云端。

开发环境配置见[配置说明](configuration.md)。构建后的预览以 `dist/server/wrangler.json` 为配置入口；如需在这个预览中测试模型，可在构建完成后执行：

```sh
cp .dev.vars dist/server/.dev.vars
npm start
```

先确认根目录的 `.dev.vars` 已填写。该文件仅用于本地运行，不会把密钥编译进浏览器资源。重新构建后应重新检查预览配置。`dist/` 和 `.wrangler/` 都不提交到 Git。

## 线上运行需要准备什么

应用按 Cloudflare Worker 运行方式构建，需要部署 `dist/server/wrangler.json` 指向的 Worker 和静态资源，并在运行环境设置[模型变量](configuration.md#本地模型配置)。生成的配置中没有真实密钥。D1 已有本地绑定，线上必须替换为实际数据库 ID 并迁移表；完整步骤见[自动订阅与推送](automation.md#部署后台任务)。对象存储尚未启用。

如果选择 Sites 托管，应通过对应平台的发布流程使用现有项目信息，并在平台设置运行环境变量。应复用 `.openai/hosting.json` 中已有的项目，不创建新项目。

如果选择自行部署到 Cloudflare Workers，需要先确定账号、Worker 名称、访问范围和域名。当前分析接口检查同源请求，但没有应用层登录、访问权限或调用频率限制；`app/chatgpt-auth.ts` 尚未接入分析流程。若站点只供指定用户使用，应先配置平台访问控制，并确认未授权用户无法调用分析接口。不要仅凭 Origin 检查就认为服务是私有的。

目标平台和访问方式确定后，用该平台的工具部署构建产物和设置服务端密钥。不要将本地 `.dev.vars` 当成可公开的发布附件，也不要把私人仓库当成网站访问控制。

## 发布前后如何验证

发布前按[测试与验证](testing.md)检查代码，并确认模型配置、访问控制和域名设置符合预期。发布后检查页面和静态资源、`/api/status`、未授权访问，以及一次真实分析。调用失败、超时和模型结果不合规时，页面应保留原文章并提示原因。

当前首页从 D1 读取事件与配置，报告在设置弹窗中查看，本地和线上数据库分别保存；发布不会把本地真实文章或密钥上传。旧收藏与阅读记录仍在原浏览器中，不恢复旧数据；新收藏只保存事件与文章 ID。定时任务与渠道配置见[自动订阅](automation.md)。

2026-10-11 的极简前端改版仅完成本地开发和验证，尚未部署。GitHub 源码可能比现有私人站点更新，发布状态见[阶段验收](acceptance.md)。
