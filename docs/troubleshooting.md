# 常见问题

## 克隆仓库提示无权限

项目为私人仓库，确认 GitHub 账号及 Git 凭据具有访问权限。不要通过公开仓库绕过权限。

## 安装或启动失败

按[开发环境](configuration.md#开发环境)确认 Node.js 版本，执行 `npm run install:ci`。找不到 Vinext 时不要用全局安装替代锁定依赖。开发服务保持 `npm run dev` 运行，并使用打印的地址；端口占用时使用实际地址。修改模型配置后重启服务。

## 从哪里开始检索并发送

首页输入管理口令连接，点击“检索并生成报告”，报告出现在下方后再点击“推送这份报告到飞书”。生成报告本身不发送；手动推送立即发送，不受每日开关和时间限制。来源和每日自动任务在右上角“设置”维护，详见[操作流程](automation.md#手动检索生成报告和推送飞书)。

## 新增 0 篇或没有公众号文章

新增 0 可能表示来源没有新内容或文章已入库，已有文章仍可生成报告。到设置查看来源最近读取时间与错误。当前读取已配置的 RSS/Atom，不直接读取微信关注列表，不是全网搜索。公众号需要接入订阅服务后添加地址。

## 生成等待、部分完成或失败

等待表示还没有通过校验的分析；部分完成表示报告只包含成功结果，其余文章保留待处理。可再次生成或等待后台任务。最近 24 小时没有内容则显示暂无资讯。错误详见设置里的处理记录。

| 原因 | 处理 |
| --- | --- |
| 模型尚未配置 | 检查三个模型变量和 HTTPS 基础地址，重启或部署后重新连接。 |
| 额度不足、请求过多或服务错误 | 检查服务商账号、模型名称、密钥权限和额度。 |
| 连接失败或超时 | 检查 Worker 到服务商的网络；请求超时后先刷新查看后台结果。 |
| 无法解析、引文无法定位或格式不完整 | 确认支持 JSON mode，查看具体错误再重试；不关闭证据校验。 |
| 分组包含不同事件 | 文章保留，管理员可通过后台拆分接口修正；前端当前没有拆分页。 |

分析接口规则见[实现说明](implementation.md#分析接口)。模型没有外部事实核查能力，多源提及仍不等于已证实。

## 推送按钮不能点击或发送失败

只有本次手动生成、包含有效内容且未超过 23 小时的报告可立即推送。每日历史和旧预览需先重新生成报告。没有飞书配置时先在服务端填写 Webhook。发送成功后禁用重复推送；失败最多三次尝试，达到上限需检查配置。送达不明时停止重发，先查看群消息。接口接收成功不等于已经人工确认群送达。

生成或推送请求超时后，点击刷新查看记录；后台忙碌时等待任务结束，不重复操作。只读刷新失败不会表示报告被清除。

## 旧空简报、预览与当前报告的状态不同

历史记录属于不同时间、不同报告，生成与发送状态各自保存。旧版本的空简报保留记录，但不会阻止当天自动任务补充有效内容。首页选择可用报告，也可展开历史查看指定记录，不能根据某个旧预览判断新报告是否送达。

## 刷新后需要重新连接或旧收藏不见了

管理口令只在页面内存保存，刷新后重新输入。真实文章、报告与设置在 D1 中，重新连接后读取。旧收藏和阅读记录仍留在原浏览器，但当前前端没有入口，也不读写它们；无需为此清除网站数据。

## 要求没有生效，或 Jev 尚未配置

解析要求只填写草稿，检查关键词并点击“保存并应用”后再生成新报告。旧报告保留原来的内容和要求。关键词不是任意自然语言条件的完整执行器，规则范围与限制见[搜集要求](collection-policy.md)。Jev 显示未配置时检查服务端 `JEV_API_KEY`；本地填写后重启，线上另外设置 Secrets。有配置但初筛失败时，查看处理记录；程序不会把这些文章绕过初筛直接交给分析模型。
