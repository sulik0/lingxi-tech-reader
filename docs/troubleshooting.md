# 常见问题

## 克隆仓库提示无权限

这是私人仓库。确认你登录的 GitHub 账号有访问权限，且 Git 使用的 HTTPS 凭据或 SSH 密钥属于这个账号。不要通过公开仓库来绕过权限问题。

## 安装、测试提示 Node.js 版本不支持

先执行 `node --version`，再按[开发环境](configuration.md#开发环境)切换版本。测试直接导入 TypeScript 文件，旧版 Node.js 无法按当前方式运行。切换后重新执行 `npm run install:ci`，避免沿用不完整的依赖目录。

如果提示找不到 Vinext，也先运行上述安装命令；不要把全局安装的 Vinext 当成项目的锁定依赖。

## localhost 页面打不开，或改动没有出现

确认开发终端仍在运行 `npm run dev`，并使用它打印的地址。开发入口见 [Quick Start](../README.md#quick-start)；`npm start` 是构建后预览，地址可能不同，且必须先构建，见[构建与部署](deployment.md#构建和本地预览)。

端口被占用时，关闭你自己启动的旧服务，或按终端提示使用实际地址。改了模型变量后需要重启服务并刷新页面。

## 添加公众号后没有收到文章

手动导入区域的来源名称只用于筛选。要自动收集，请在上方“自动订阅与每日推送”添加 RSS/Atom 地址，并检查最近读取记录。详见[自动订阅与推送](automation.md)。通过“导入文章”也可以粘贴正文；只提供文章链接不会自动读取文章。实际处理步骤见[导入、去重与分组](implementation.md#导入去重与分组)。

## 界面显示 AI 已连接，但分析失败

“已连接”只表示配置项齐全，见[怎样确认配置生效](configuration.md#怎样确认配置生效)。按返回原因处理：

| 提示或状态 | 处理方法 |
| --- | --- |
| 503：尚未配置或服务地址无效 | 检查三个模型变量、HTTPS 基础地址和配置文件所在位置，然后重启。 |
| 502：服务返回错误、额度不足或请求过多 | 在模型服务侧确认密钥、模型名称、接口权限和额度。应用不会显示服务商的原始错误内容。 |
| 502：连接失败或超时 | 检查 Worker 是否能访问服务地址，稍后重试；请求超时规则见[模型调用](implementation.md#模型调用)。 |
| 502：无法解析、证据无法定位或格式不完整 | 确认模型支持 JSON mode，再重试。不要为了显示结果而关闭引用和格式检查。 |
| 422：文章可能讨论不同事件 | 在文章预览中把不相关的文章拆分后重新分析。 |
| 400 或 413：字段或大小不符合要求 | 按[接口限制](implementation.md#请求字段和大小限制)减少文章数量、正文或请求大小。 |
| 403 或 415：请求来源或格式无效 | 从同一地址的工作台提交 JSON 请求；自己调试接口时检查 Origin 与 Content-Type。 |

文章在分析失败时仍保存在当前浏览器中。错误状态的完整含义见[响应与错误](implementation.md#响应与错误)。

## 文章被分到了错误的事件

标题相似度只能做初步判断。从阅读室打开文章预览，点击“拆分为独立事件”，再分析各个事件。当前没有任意合并事件的操作；算法细节和重新分析行为见[导入、去重与分组](implementation.md#导入去重与分组)。

## 刷新后数据丢失，或换个地址没有原来的文章

数据按浏览器和站点 Origin 保存。`localhost`、`127.0.0.1`、不同端口和线上域名各有自己的阅读空间；它们不会自动同步。无痕会话结束、清除网站数据或浏览器存储失败，也会影响保存。

先确认地址和浏览器是否相同。出现存储不足提示时，尽快在设置里导出 JSON，保留本次阅读空间。不要直接清理网站数据；当前没有从 JSON 恢复的界面，也没有服务器备份。详见[保存与导出](implementation.md#保存与导出)。

## 导入达到上限后怎样清理

当前界面没有删除文章或按事件清理的入口。先导出阅读空间；若决定重置，只能通过浏览器的网站数据管理清除该站点的本地数据，这会同时移除文章、收藏和阅读记录。导出的 JSON 可留存，但尚不能通过应用导回。

## 停用来源后，重新分析发现文章少了

这是当前实现限制。来源筛选会改变提交的文章集合，分析成功后可能覆盖事件中的隐藏文章。分析前启用全部相关来源并导出 JSON。已经被覆盖的文章需要重新导入；详见[已知实现限制](implementation.md#已知实现限制)。
